## 1. 逐层决策记录(选了什么 / 为什么 / 备选是什么)

### 1.1 操作系统层:复用已有 WSL2 Ubuntu-22.04,不新建发行版

- **现状**:机器已有 WSL2 + Ubuntu-22.04(正在运行,里面跑着 k3s)。
- **决策**:直接复用。新建 24.04 发行版没有任何收益,反而多占一份 vhdx。
- **GPU 透传验证(验收 A)**:WSL 内 `nvidia-smi` 正常显示 RTX 4070 Ti SUPER 16376MiB;
  `/usr/lib/wsl/lib/` 下是微软注入的用户态 CUDA 库——**符合"WSL 内不装 Linux 显卡驱动"的硬约束**。
- **已做的清理**(经你确认):`systemctl disable --now k3s`(原先做 ONES 部署测试用)。
  恢复命令:`sudo systemctl enable --now k3s`。之后建议 `wsl --shutdown` 一次彻底回收内存。
- **为什么不用 Docker**:docker-desktop 发行版存在但已停止;原生 pip 安装更轻、改源码更直接,
  学习期直接操作比套一层容器更透明。(vLLM/SGLang 官方也有 CUDA 镜像,以后要复现 CI 问题时再用。)

### 1.2 GPU/驱动层:完全不动

- Windows 驱动 617.42 / CUDA 13.4 足够新,直接支撑 CUDA 13 栈的 wheel(torch 2.13/2.14 + cu130)。
- **没做**(按安全边界):升级驱动、迁移 WSL 磁盘。
- sm_89(Ada)特性:支持 INT4/FP8 tensor core;16GB 显存、672GB/s 带宽是后面所有性能数字的物理约束。

### 1.3 Python 层:Miniconda + 3 个隔离环境

- **选择 Miniconda 而不是系统 Python/venv/uv**:系统 Python 是 3.10(vLLM 支持但偏旧);
  conda 能任意定 Python 版本、环境隔离语义清晰、你在 Windows 侧本来就熟 Anaconda;
  uv 更快但对初学者黑盒更多。
- **版本**:Miniconda 26.9.4(清华镜像安装,`~/miniconda3`,已 `conda init bash`)。
- **三个环境,各有用途**:

| 环境 | 内容 | 用途 | 为什么分开 |
|---|---|---|---|
| `vllm` | vLLM 0.32.0 wheel + torch 2.13.0+cu130 | **基线测试**(数字可信,不被开发改动污染) | wheel 稳定版 |
| `vllm-dev` | vLLM 0.32.0+precompiled(源码可编辑) | **改源码做实验** | editable 指向 ~/dev/vllm |
| `sglang` | SGLang 0.5.22 + torch 2.14.1 | 对照学习 | torch 版本都和 vllm 环境不同(2.14 vs 2.13),混装必炸 |
| `cudatoolkit` | cuda-nvcc 13.x + cudart-dev + cccl(无 Python) | 共享的 nvcc,给 SGLang/vLLM 的 flashinfer JIT 用 | 一个工具链服务所有环境,`CUDA_HOME` 指向它即可 |

- **镜像配置**:`~/.condarc`(清华 anaconda 镜像)、`~/.config/pip/pip.conf`(清华 PyPI)。
- 附加安装(都在 vllm 环境):`modelscope`(国内模型下载)、`nvitop`/`gpustat`(GPU 监控)、
  `pytest`(vllm-dev 环境,跑源码测试)。

### 1.4 推理框架层

- **vLLM 0.32.0**(2026-10 当前最新稳定版):`pip install vllm`,依赖链自动装齐
  torch 2.13.0+cu130、flashinfer-python 0.7.0.post1、triton 3.7.1、transformers 5.19.0 等。
- **SGLang 0.5.22**:`pip install "sglang[all]"`。
- **源码仓库**:`git clone --depth 1` → 201MB;**已切到 v0.32.0 标签**(原因见 1.6)。

### 1.5 模型层(全部 ModelScope,国内 CDN 很快)

| 模型 | 大小 | 用途 | 备注 |
|---|---|---|---|
| Qwen/Qwen3-1.7B | 3.8GB | 快速验证、开发调试 | bf16,秒级加载 |
| Qwen/Qwen3-8B-AWQ | 5.6GB | 基线 + prefix 实验 | 4-bit 量化 |

- **量化选型:AWQ-INT4,而非 GPTQ-INT4 / FP8**:
  1. ModelScope 上 Qwen 官方 8B 的 INT4 版只有 AWQ(GPTQ-Int4 仓库不存在,实测 404);
  2. 16GB 显存下 INT4 权重 5.6GB,KV cache 可用 ~9GB,并发容量最大化;
     FP8 权重 ~8.5GB 会挤掉一半 KV cache 空间;
  3. vLLM 中 AWQ 走 **Marlin 内核**(启动日志确认 `Using MarlinLinearKernel`),
     在 Ada 消费卡上与 GPTQ 同级速度。
- 下载命令:`modelscope download --model Qwen/Qwen3-8B-AWQ --local_dir ~/models/Qwen3-8B-AWQ`

### 1.6 源码开发层:可编辑安装的关键细节(验收 D)

- 标准流程:`cd ~/dev/vllm && VLLM_USE_PRECOMPILED=1 pip install -e .`
  原理:编译产物(C++/CUDA 扩展)直接取官方发布 wheel 的,Python 代码指向源码树 → **改 .py 重启即生效**。
- **踩坑记录**:在 main 分支 HEAD(8701c9b)上安装失败——
  `No published precompiled wheel for variant cu130 within 20 commits of <HEAD>`
  (main 的 nightly 产物有时滞)。**解法:checkout v0.32.0 标签再装**,一次成功,
  得到 `vllm 0.32.0+precompiled`,`vllm.__file__` 指向 `~/dev/vllm/vllm/__init__.py`。
- **改动生效验证**:在 `vllm/entrypoints/openai/chat_completion/serving.py` 注入
  `logger.warning("MARKER-EDITABLE-OK")`,用 vllm-dev 环境启动,服务日志立即出现该行,
  且 API 正常应答(验证后已 `git checkout --` 还原)。
- **注意**:0.32 的源码布局和老教程不同——chat 接口在
  `vllm/entrypoints/openai/chat_completion/serving.py`(不再是不存在的 `serving_chat.py`)。

### 1.7 系统工具层(WSL 内,经 root 直连安装,均不涉及显卡驱动)

- `build-essential`(gcc 11.4):**必需**——vLLM 启动时 Triton/Inductor JIT 编译需要 C 编译器,
  缺失时报 `InductorError: Failed to find C compiler`,这是本次环境最核心的一个坑。
- sudo 需要密码,自动化不可用;改用 `wsl -d Ubuntu-22.04 -u root -e bash -c "..."`(WSL 标准能力)。

## 2. 已知限制与遗留项(诚实清单)

1. **flashinfer-cubin 0.7.x 未装上**(官方源仅 flashinfer.ai,本机直连极慢;PyPI 镜像最高 0.6.13)。
   **已落地的替代方案**:
   - 新建了共享的 conda 环境 **`cudatoolkit`**(cuda-nvcc + cuda-cudart-dev + cuda-cccl,
     来自 nvidia 官方 conda 频道,约 300MB),提供真实 nvcc;
   - **SGLang**:启动前 `export CUDA_HOME=~/miniconda3/envs/cudatoolkit` +
     `export LIBRARY_PATH=~/cuda-libs:$CUDA_HOME/lib`(~/cuda-libs 是手工造的链接垫片:
     `libcuda.so→/usr/lib/wsl/lib/libcuda.so.1`、`libcudart.so→cudatoolkit 环境里的副本`,
     因为 WSL 透传目录只有 `.so.1` 没有开发用无版本号符号),
     flashinfer 走 JIT 编译(首次编译几分钟,结果缓存在 ~/.cache,之后不再编);
   - **vLLM**:同理可用;但更简单的是 `VLLM_USE_FLASHINFER_SAMPLER=0`(采样走 Triton)。
   - 若以后挂代理,可补 `pip install flashinfer-cubin==<匹配版本> --index-url https://flashinfer.ai/whl`
     彻底消灭 JIT。
2. **源码仓库是浅克隆 + 停在 v0.32.0 标签**:做 `git bisect` 前需要
   `git fetch --unshallow`(~1GB);追新 main 需 `git fetch origin main`。
3. **内存预算**:WSL VM 上限 20GB(`.wslconfig` 你已配好)。8B 推理本身够用;
   k3s 已停用(恢复:`sudo systemctl enable --now k3s`)。
4. **Windows 侧 localhost 代理不透传到 WSL**(NAT 模式):WSL 内访问国外源慢的根因。
   国内镜像已覆盖绝大部分需求;个别国外源操作建议在 Windows 侧下载后拷入 WSL。

## 5. 合理性校验(对照原提示词的 40~90 tok/s 区间)

8B-AWQ 权重 5.6GB ÷ 672GB/s ≈ 理论单流上限 120 tok/s(比提示词按 8GB 估的 84 更高,因为 AWQ 压得更小)。
实测单流落点与 4 档并发数据见《基线数据.md》——确认量化生效(Marlin 内核)、GPU 计算未被 CPU/内存拖累。
